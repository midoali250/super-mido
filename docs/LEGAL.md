# Legal and content policy

Short version: **this repository contains a tool. It contains no games.**

## What is in here

- A cartridge-header parser for the public iNES / NES 2.0 file formats
- A 6502 disassembler (official and undocumented NMOS opcodes)
- A 6502 assembler, used to prove the disassembler round-trips
- A CHR-ROM tile decoder
- Tests that build their own cartridge images from scratch

Every byte in this repository was written by the contributors or generated by
the test suite at runtime. There are no cartridge images, no ROM files, no
extracted assets, and no disassembly listings of any commercial game.

## What is deliberately *not* in here

| Excluded | Why |
|---|---|
| `*.nes`, `*.fc`, `*.fds` and any other cartridge image | Game programs are copyrighted works. Distributing them is not permitted by this project. |
| Disassembly or decompilation output for a commercial title | A listing of someone else's program is a derivative work of it. Publishing one is legally contested even when the ROM itself is absent. |
| Extracted graphics, audio, palettes, text or level data | Same reasoning: these are the copyrighted expression, not the format. |
| Any third-party trademark as a project, file, symbol or test name | Avoids implying affiliation or endorsement. |

`.gitignore` enforces the first category mechanically, and CI fails the build
if a cartridge image is ever committed.

## What you are allowed to do with the tool

Use it on images you are entitled to use. In most jurisdictions that means an
image you created yourself from a cartridge you own, for your own study. The
legal position on dumping and on reverse engineering varies by country; this
document is not legal advice and the authors are not lawyers.

The tool makes no attempt to obtain images for you. It takes a path you give
it and reads that file.

## Why the test suite builds its own images

The tests need real cartridge images to parse. Rather than ship one, the suite
assembles small programs from 6502 source and wraps them in a valid header at
runtime (`tests/fixtures.py`). This gives the tests deterministic, inspectable
input with known expected output -- which is better testing anyway -- and keeps
the repository free of third-party material.

## Prior art

Mature decompilation projects follow the same rule: the repository holds
source and build tooling, and the user supplies their own image, which is
never committed. That pattern is what keeps those projects available.

## If you own rights to something in here

If you believe content in this repository infringes your rights, open an issue
or contact the maintainer and it will be removed promptly. The maintainer has
no interest in hosting anyone else's work.
