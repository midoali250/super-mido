# SuperMido

A 6502 cartridge-analysis toolkit: header inspection, disassembly with real
code/data separation, pointer-table recovery, symbol files, round-trip
verification, and CHR tile decoding.

Standard library only. No runtime dependencies.

**This repository contains a tool. It contains no games.** Every byte here was
written by the contributors or generated by the test suite at runtime. See
[`docs/LEGAL.md`](docs/LEGAL.md) — that policy is enforced by `.gitignore`, by
CI, and by the test suite itself.

---

## Why this exists

Most 6502 disassemblers do a linear sweep: start at the first byte, decode
whatever is there, move on. That reads a sprite table as `ORA ($41,X)` and a
pointer table as a jump into the middle of nowhere. The output looks plausible
and is wrong in the places that matter.

SuperMido disassembles from the interrupt vectors instead, following every
branch, jump and call it can reach, and emits everything else as explicitly
labelled data. Then it **proves its own output**: the assembler re-encodes
every instruction and compares against the original bytes. A listing that does
not round-trip is a listing you should not trust.

## Features

| | |
|---|---|
| **Header parsing** | iNES, iNES 0.7, archaic iNES and NES 2.0, using the recommended detection procedure. Mapper up to 4095, submappers, mirroring, trainer, battery, four-screen, Vs. and PlayChoice flags. |
| **Dump forensics** | Detects ripper signatures in the padding bytes (`DiskDude!` and friends) and masks the inflated mapper number back off, instead of silently reporting mapper 68 for mapper 4. |
| **Full 256-opcode table** | All 151 official NMOS instructions plus 105 undocumented ones (`SLO`, `RLA`, `SRE`, `RRA`, `DCP`, `ISB`, `SAX`, `LAX`, `ANC`, `ALR`, `ARR`, `AXS`, …). Unstable ones are flagged rather than silently decoded. |
| **Two strategies** | `recursive` (vector-driven, separates code from data) and `linear` (decodes every byte). |
| **Round-trip verification** | `supermido verify` re-assembles the listing and diffs the bytes. Zero mismatches, or it tells you exactly which addresses diverged. |
| **Cross-references** | Every absolute operand is recorded as an xref; branch and jump targets get labels. |
| **Pointer-table recovery** | Finds runs of little-endian words that point inside PRG ROM, emits them as `.word` instead of fake instructions, and follows every target -- so handlers reached only through an indexed load are no longer invisible to `recursive`. |
| **Symbol files** | Reads FCEUX `.sym` and Mesen `.mlb`, writes `.sym`. Naming accumulates across sessions instead of resetting to `LC013`. |
| **CHR decoding** | Two-bitplane tile decoding to text or PGM, plus blank/solid/used statistics for spotting graphics banks. |
| **Zero runtime dependencies** | Standard library only. Python 3.10+. |

## Install

```bash
pip install -e ".[dev]"
```

## Use

```bash
# Header forensics
supermido inspect my-cart.nes
supermido inspect my-cart.nes --json

# Disassemble from the vectors, separating code from data
supermido disasm my-cart.nes --mode recursive --out listing.asm

# Or decode every byte
supermido disasm my-cart.nes --mode linear --json --out listing.json

# Prove the listing round-trips
supermido verify my-cart.nes

# Look at the graphics
supermido chr my-cart.nes --pgm tiles.pgm
supermido chr my-cart.nes --tiles 16 --columns 4
```

Just want something to point it at? Generate a synthetic cartridge — a small
6502 frame loop this project assembles itself:

```bash
python tools/make_sample.py --out /tmp/sample.nes
supermido inspect /tmp/sample.nes
supermido disasm /tmp/sample.nes
```

## Layout

```
src/supermido/
  ines.py      header parsing, format detection, dump validation
  cpu6502.py   the 256-entry opcode table and operand formatting
  asm6502.py   two-pass assembler with a fixed-point sizing loop
  disasm.py    linear + recursive strategies, xrefs, round-trip check
  chrrom.py    CHR two-bitplane tile decoding
  cli.py       the supermido command
tests/
  fixtures.py  builds synthetic cartridge images from 6502 source
  test_*.py    50+ tests, no external data
tools/
  make_sample.py     generate a synthetic image to try the CLI on
  check_policy.py    the content-policy checker CI runs
  rename_project.py  rename the whole project in one pass
docs/
  LEGAL.md           the content policy, and why it is written this way
  ARCHITECTURE.md    module graph and the design rules
Makefile             install / test / lint / policy / demo / check
CONTRIBUTING.md      what gets a PR closed, and good first issues
CHANGELOG.md
```

## Development

```bash
make check     # lint + test + policy -- exactly what CI runs
make demo      # build a synthetic cartridge and walk it through the CLI
```

Or directly:

```bash
pytest -v      # the suite builds its own test images, no fixtures to fetch
ruff check src tests tools
python tools/check_policy.py
```

`tests/fixtures.py` is the interesting one. It assembles small 6502 programs
and wraps them in a valid iNES header, so the tests get deterministic input
with known expected output. That is better testing than a binary blob, and it
is why this repository needs no external data of any kind.
